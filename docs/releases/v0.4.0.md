# cgx v0.4.0 — Go SDK, C and C++, and receiver narrowing

cgx now runs as an embeddable engine. A Go SDK ships the indexer and query
engine as a reproducible WebAssembly module. C and C++ join the supported
languages, and virtual call sites can be narrowed by receiver type.

## Go SDK and WebAssembly engine

- **Go SDK** (`github.com/ferralon-ai/cgx/sdk/go`) — index and query a
  repository from Go through an embedded `cgx.wasm` engine, with no native
  binary to install. It is published as `sdk/go/v0.4.0` (#19).
- **wasm32-wasip1 build** — the engine compiles to WebAssembly with a
  reproducible `cargo xtask wasm` build. Each release attaches the module and
  its sha256 (#15). The published hash is the Release asset's; the reference
  build host is x86_64-unknown-linux-gnu (see `docs/releases/README.md`).
- **Typed MCP output** — every MCP tool now declares an output schema and
  returns structured content (#13).

## Languages

- **C and C++ adapters**, with scip-clang wiring for compiler-accurate
  resolution (#25). Two scip-clang relabel fixes, for orphan candidates and
  certain-redirect targets (#33).
- **Symbol roots from manifests.** Fully qualified names are now rooted in each
  ecosystem's package identity:
  - Rust takes the Cargo package name (#8);
  - Go takes the go.mod import path (#11);
  - Python takes the module path (#9);
  - TypeScript and JavaScript take the package.json name (#10).

  This builds on the generalized manifest resolution in #7 and on `/` becoming
  a segment boundary alongside `::` (#6).

## Precision

- **Receiver narrowing** (opt-in) — virtual call sites can be narrowed by
  receiver kind (#21), with intraprocedural receiver typing for Python and
  VTA-lite for Go (#23). Narrowing has its own approximation contract (#17).
  It builds on the receiver-typing fact channel in #16, and #31 makes it treat
  a suffix-matched import that cannot serve the member as out of repo.
- **Data flow** — summary call sites are grounded through the resolved call
  (#26).
- **Extraction fixes:**
  - JSX is parsed with the TSX grammar (#18);
  - `const` TypeScript closure calls resolve lexically (#20);
  - CommonJS `exports.x` and `module.exports.x` definitions are registered
    (#36);
  - Go `if` initializers are walked (#38);
  - every Python `elif`/`else` branch is walked (#39);
  - the inner call of a chained call such as `f(x).g()` is kept (#40).
- **CQL** — variable-length patterns now find cycles and self-recursion (#37).

## MCP server

- Answers come from the persistent `.cgx/` index; uncommitted changes go into
  an in-memory overlay that is never persisted, instead of a re-index on every
  call (#32).
- With `--root`, every tool call is confined to the configured root (#41).

## Performance and storage

- The SQLite shadow store is retired (#28).
- Object durability is batched, and objects are verified on read (#27).
- Shards are encoded with stable keys, so an edit rewrites only the shards it
  touches (#30).
- Whole-graph copies are gone from the indexing memory peak (#22), and resolved
  edges are stored in fixed-size chunks (#34).
- Lookups are faster: suffix module matching is indexed by last segment (#14),
  and CHA nodes are looked up by id instead of scanned (#24).
- The fragment cache is keyed by blob plus path context (#29), and fragments
  cached under a different frontend version are re-extracted (#12).

## Release engineering and docs

- A floating minor alias `vX.Y` tracks the newest patch on each minor line
  (#3).
- The README, docs and agent skill are refreshed (#35).
