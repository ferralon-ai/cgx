## About this glossary

Terms are listed alphabetically. Each entry gives a plain-language definition (1–3 sentences) followed by cross-references to the feature IDs where the term is specified and "See also" links to related glossary entries. Readers are assumed to have passing familiarity with query-language concepts; every jargon term used in a breakdown in the question cookbook is defined here.

Canonical terms must not be replaced with synonyms. If a term appears in the docs with a different name, that is an error; update doc 03 or doc 04 rather than coining a new term.

## Terms

**abstract-method fulfillment** — The mapping from a concrete method to the abstract declaration (`is_abstract = true`) it satisfies, recorded as a `fulfills` edge. A concrete type with an abstract member left unfulfilled through its [MRO](#method-resolution-order-mro) is reported by the derived `unfulfilled_abstract` predicate. → GM-25; See also: [method resolution order (MRO)](#method-resolution-order-mro), [override](#virtual-dispatch)

**accessor override (property shadowing)** — A subclass getter, setter, or property that overrides a parent accessor or shadows a parent field, changing the read/write semantics of an attribute access. Recorded as an `overrides` edge over accessor symbols plus a `shadows-field` edge to the shadowed field. → GM-24; See also: [virtual dispatch](#virtual-dispatch)

**acquiring** — The act of locking or opening a resource at the start of a resource lifecycle pair. Every acquire call must be paired with a corresponding [release](#release) call on every execution path, including [exceptional class](#exceptional-class) paths. → GM-13; See also: [resource lifecycle pair](#resource-lifecycle-pair), [release](#release)

**any-frontier** — Informal name for a [type-confidence boundary](#type-confidence-boundary): the call site or assignment where a value crosses from a statically-typed binding into `any`/`interface{}`/`dynamic`/reflection territory (or back). The `any`-frontier query (Q-30) enumerates these crossing points. → GM-14.6, Q-30; See also: [type-confidence boundary](#type-confidence-boundary), [lineage type reconstruction](#lineage-type-reconstruction)

**avoiding** — A path-quantifier clause in the `cgx` query language (`MATCH ALL … AVOIDING`) that asserts all paths from a source to a sink do NOT pass through a named node. When combined with `--assert-empty`, zero results confirm a must-pass-through guarantee. → Q-20; See also: [must-pass-through](#must-pass-through), [path quantifier](#path-quantifier)

**blast radius** — The set of symbols affected by a change to a given function or type: its callers (who depends on it) and callees (what it depends on), traversed transitively to a chosen depth. Blast-radius queries scope the impact of an edit before it is made. → Q-2, Q-13 (depth limits); See also: [reachability](#reachability), [slicing](#slicing)

**blob OID** — The git content-hash identifier for a single source file at a specific version. `cgx` uses blob OIDs as the primary cache key for per-file graph facts: if a file's blob OID is unchanged across branches or commits, its facts are a cache hit and the file is not re-analyzed. → IX-1; See also: [branch-aware incremental indexing](#branch-aware-incremental-indexing), [index](#index)

**branch-aware incremental indexing** — The property of `cgx`'s index that lets multiple branches share per-file facts whenever the underlying file content (and therefore blob OID) is the same. Only files whose blob OID changed between two tree OIDs are re-analyzed; unchanged files cost nothing. → IX-1, IX-2, IX-4; See also: [blob OID](#blob-oid), [index](#index), [prune](#prune)

**build-configuration variance** — The dependency of which nodes and edges exist in the graph on compile-time or build-time conditions such as Rust feature flags, C preprocessor defines, and Go build tags. `cgx` records these as [cfg-condition](#cfg-condition) attributes; full per-configuration indexing is roadmap status. → GM-19

**call edge** — An [edge](#edge) representing the invocation of one callable by another. The call-edge types are `calls` (direct), `calls:virtual` (interface/trait dispatch), `calls:closure`, `calls:callback`, `calls:async` (await point), and `calls:indirect` (function pointer). Every call edge carries an [edge condition](#edge-condition) label; `spawns` is a separate edge kind for detached launch. → GM-2.1, GM-9; See also: [edge](#edge), [edge condition](#edge-condition), [virtual dispatch](#virtual-dispatch)

**CALL … YIELD** — The query-language form for invoking a named procedure that returns multiple columns of results. Only two procedures are defined: `cgx.type_reconstruct` (lineage type reconstruction) and `cgx.mutation_fanout` (outbound mutation analysis). Their yielded columns bind like node properties and compose with `WHERE` and `RETURN`. → docs/05-queries.md Layer 2 "Procedure calls"; See also: [procedure](#procedure), [Layer 2](#layer-2), [lineage type reconstruction](#lineage-type-reconstruction), [mutation fan-out](#mutation-fan-out)

**call-site node** — A subordinate node kind (`call-site`) identifying a specific call expression within a caller's body by its `(caller, file, line, col)` identity. Call-site nodes are never returned by symbol queries and never appear in `nodes(path)`; they are accessed via the `r.site` join on a call edge. Phase-1 attributes: `caller`, `file`, `line`, `col`, `ordinal`, `suspends`. Schema-room attributes (Phase 3): `cfg_block`, `dominating_sites`, `lock_set`, `is_return_site`. → GM-1.4, ADR-01; See also: [dominance](#dominance), [lock set](#lock-set)

**candidate set** — The set of possible runtime call targets that `cgx` associates with a single call edge when the callee cannot be uniquely resolved. Virtual dispatch, function pointers, and indirect calls produce candidate sets; the set is stored as an attribute on the edge and is bounded by the resolution tier. → GM-2.1, GM-5; See also: [confidence](#confidence), [virtual dispatch](#virtual-dispatch), [cut marker](#cut-marker)

**capture edge** — A `calls:closure` edge or a `derived-from` edge annotated with an escape kind of `closure-capture` that models a closure or lambda capturing a variable from its enclosing scope. Capture edges carry [mutability](#mutability) attribution: a `move` capture is `binding`-immutable inside the closure; a by-reference capture is `alias`-mutable. → GM-2.1, DF-16.1, DF-18.2; See also: [closure](#closure), [function value](#function-value), [mutability](#mutability)

**certain** — The highest [confidence](#confidence) tier. An edge is `certain` when it was resolved by direct static binding with no ambiguity — a non-virtual call, a monomorphized Rust generic, or a SCIP occurrence with exactly one target. → GM-5.1; See also: [probable](#probable), [possible](#possible), [confidence](#confidence)

**cfg-condition** — An attribute on a node or edge that records the build-configuration condition (Rust `#[cfg(...)]`, C `#ifdef`, Go build tag, etc.) under which that node or edge is present in the graph. A null `cfg-condition` means the element is unconditionally present. Reserved for future per-configuration graph indexing. → GM-19; See also: [build-configuration variance](#build-configuration-variance)

**class-matched sanitization** — A sanitization rule that clears a taint label only when the sanitizer's declared class matches the sink class of the label. A sanitizer declared for class `html` does not clear `sql`-destined taint, preventing cross-context false negatives. → DF-11.2, DF-12; See also: [sanitizer](#sanitizer), [typed taint](#typed-taint), [sink](#sink)

**closure** — An anonymous callable that captures variables from its enclosing scope. Closures are represented in the graph as `lambda` nodes (GM-1.1) and invoked via `calls:closure` edges. Their captures are tracked as [capture edges](#capture-edge) and participate in [mutation fan-out](#mutation-fan-out) and pedigree queries. → GM-1.1, GM-2.1, DF-18; See also: [capture edge](#capture-edge), [function value](#function-value), [lambda](#lambda)

**coerce** — A `derives-from` transformation kind written `coerce(from, to)` that marks a program point where a value's type changes through an implicit conversion (e.g. `coerce(string, int)` in a PHP authentication check, or `coerce(any, User)` at a TypeScript type assertion). Mutability and taint are re-evaluated at the destination type after a coercion. → DF-10.2, DF-17.5; See also: [lineage type reconstruction](#lineage-type-reconstruction), [type-confidence boundary](#type-confidence-boundary)

**COMPATIBLE_WITH** — A query-language predicate that tests structural type compatibility between two types; returns false when the two types share no common subtype. Used in type-reconstruction queries to test whether a candidate type is consistent with the constraints found in a given direction. → docs/05-queries.md Layer 2 "Predicates"; See also: [lineage type reconstruction](#lineage-type-reconstruction), [IS EMPTY](#is-empty)

**confidence** — A deterministic label on every node and edge that records how well-founded the static resolution was. The three values are `certain`, `probable`, and `possible`; they correspond to resolution tiers 0–4 on the resolution ladder. Confidence is not a probability score; it is derived from the algorithm that produced the fact. → GM-5; See also: [certain](#certain), [probable](#probable), [possible](#possible), [resolution tier](#resolution-tier)

**contract** — A metadata semantic class meaning the annotation on a symbol carries a value constraint (nullability, precondition, range constraint, or type contract). Lowered to a DF-14 annotation on the symbol node; feeds nullability and optionality flow analysis. → GM-15.1, FW-2 (`contract`); See also: [metadata fact](#metadata-fact), [semantic class](#semantic-class)

**core-extension** — A status tag applied to features that are high-leverage extensions of the MVP core, derivable from the existing graph structure, and planned from the outset. Core-extension features are not in the initial MVP but are committed to the current design cycle and will be implemented before any roadmap feature. → docs/11-roadmap.md; See also: [schema-room](#schema-room), [roadmap](#roadmap)

**cut marker** — An attribute on an edge that signals the static resolution was incomplete and the edge required external evidence or could not be resolved. The five cut-marker values are `reflective`, `dynamic`, `via-DI`, `via-FFI`, and `unresolved`. Cut-marker edges are still queryable; the choice to include or exclude them is left to the query author. → GM-5.3; See also: [reflective](#reflective), [via-DI](#via-di), [via-FFI](#via-ffi)

**dataflow edge** — An edge in the graph that encodes value derivation between symbols, primarily `derives-from` edges. Dataflow edges are the backbone of [pedigree](#pedigree), [taint analysis](#taint-analysis), and [forward slicing](#slicing). → GM-2.2, DF-3; See also: [derives-from](#derives-from), [pedigree](#pedigree)

**default method** — An interface or trait method that supplies a body. A concrete type that does not override it inherits that body; the call resolves to the interface or trait, not the type. `cgx` records the body provider as a `provides-body` fact so it appears in the call's [candidate set](#candidate-set). → GM-23; See also: [candidate set](#candidate-set), [virtual dispatch](#virtual-dispatch)

**derives-from** — A directed edge type (from derived value to source value) that encodes how one value was produced from another. Every `derives-from` edge carries a [transformation kind](#transformation-kind) describing the semantic effect of the derivation (e.g. `copy`, `concat`, `parameterize(sql)`). Following these edges backward yields [pedigree](#pedigree); forward yields a [forward slice](#slicing). → DF-3; See also: [pedigree](#pedigree), [taint analysis](#taint-analysis), [transformation kind](#transformation-kind)

**deterministic** — A property of `cgx` answers: the same query against the same commit always produces the same output, in the same order. Determinism is enforced by stable result ordering (`--order` flag), no random tie-breaking, and content-addressed indexing. This is a hard design constraint stated in docs/01. → GM-5, Q-17, docs/01; See also: [confidence](#confidence)

**dominance** — The standard control-flow relationship where node A dominates node B if every path from the program entry to B passes through A. Used in `cgx` for the dominating-check requirement in nullability analysis (DF-14.2) and for must-pass-through reasoning (Q-20). Also used in the guarded-cut reachability algorithm (ADR-02): a call edge is deleted from the residual graph when a dominating call site in the same function calls the guard. → DF-14.2, Q-20, ADR-02; See also: [must-pass-through](#must-pass-through), [guarded-cut reachability](#guarded-cut-reachability), [path quantifier](#path-quantifier)

**dropped guard** — A form of [override-contract drift](#override-contract-drift) where the base method routes every path to a sink through a [must-pass-through](#must-pass-through) guard, but the override reaches the same sink on a path that avoids it. The override has silently removed a check (validation, authorization, redaction) the base enforced on all paths. → Q-32; See also: [must-pass-through](#must-pass-through), [guard](#guard), [override-contract drift](#override-contract-drift)

**dynamic** — A cut-marker value meaning the call site dispatches through a runtime plugin, script, or dynamic loader (`dlopen`, `require()` with a non-literal argument, `eval`). Edges carrying this cut marker cannot be statically resolved; `cgx` emits them so the gap is visible. → GM-5.3; See also: [cut marker](#cut-marker), [reflective](#reflective)

**edge** — A directed, typed, attributed relation between two [symbols](#symbol) (nodes) in the graph. Every edge carries an [edge condition](#edge-condition), a [confidence](#confidence) label, and a [provenance](#provenance) record. Call edges additionally carry a [candidate set](#candidate-set) when dispatch is ambiguous. → GM-2; See also: [call edge](#call-edge), [dataflow edge](#dataflow-edge)

**edge condition** — A first-class, queryable attribute on every [call edge](#call-edge) that encodes the runtime condition under which control takes that edge. The canonical label set has exactly five values: `always`, `conditional`, `loop`, `exception`, and `panic`. Compound labels are not permitted — every edge carries exactly one label. → GM-3; See also: [always](#always), [conditional (edge condition)](#conditional-edge-condition), [loop (edge condition)](#loop-edge-condition), [exception (edge condition)](#exception-edge-condition), [panic (edge condition)](#panic-edge-condition), [exceptional class](#exceptional-class)

**always** (edge condition) — The edge is taken on every execution of the call site; no runtime condition guards it. Used for unconditional calls and for calls inside `finally`/`defer`/cleanup blocks (the call is unconditional once that block is entered; its [transience](#transience) relative to an exception path is computed at query time, not stored in this label). → GM-3; See also: [edge condition](#edge-condition), [transience](#transience)

**conditional (edge condition)** — The edge is taken only when an explicit boolean branch is true (`if`, `when`, `match` arm, ternary). → GM-3; See also: [edge condition](#edge-condition)

**exception (edge condition)** — The edge is taken only during exceptional control flow: the call site is inside an exception handler, a Rust `?`/`Err` branch, a Go `err != nil` block, or a C sentinel check. Together with `panic`, this value forms the [exceptional class](#exceptional-class). → GM-3; See also: [edge condition](#edge-condition), [exceptional class](#exceptional-class), [panic (edge condition)](#panic-edge-condition)

**loop (edge condition)** — The edge is taken zero or more times inside a loop body (`for`, `while`, `loop`, iterator body). → GM-3; See also: [edge condition](#edge-condition)

**panic (edge condition)** — The edge is taken only on an unwinding or aborting path that cannot be recovered from in normal control flow (Rust `panic!`/`unwrap`, Go `panic`, Java unchecked throw reaching exit, C `abort` path). Together with `exception`, this value forms the [exceptional class](#exceptional-class). → GM-3; See also: [edge condition](#edge-condition), [exceptional class](#exceptional-class)

**entrypoint** — A declared root from which reachability traversal begins. Entrypoints are detected automatically per language (e.g. `main`, HTTP handlers, test functions) or declared explicitly in `cgx.toml`. Symbols not reachable from any entrypoint are labelled `unreachable`. A metadata annotation can lower to the `entrypoint` semantic class. → GM-7, GM-15.1, FW-2.1; See also: [semantic class](#semantic-class), [reachability](#reachability)

**established-by** — An attribute that records the evidence class used to infer an edge whose endpoints are not syntactically linked. It has **two distinct attribute scopes** on different edge types. On **GM-17 mediated call edges** (`calls`/`constructs` via DI, events, registries) the four values are `annotation`, `config-file`, `registration-site`, and `convention`. On **DF-20 channel-dataflow edges** (`derives-from` edges linking a channel send to its receive) the value is `channel-send-recv`, marking that the linkage comes from a structurally paired send and receive rather than a call expression. The value vocabularies do not overlap; check the edge type before interpreting the attribute. → GM-17.1, DF-20.1; See also: [mediated edge](#mediated-edge), [dataflow edge](#dataflow-edge)

**exception-contract widening** — A form of [override-contract drift](#override-contract-drift) where an override's exceptional surface (declared `throws` set plus reachable `exception`/`panic` edges) is a strict superset of the base method's, so callers written against the base's narrower failure contract are exposed to failures they did not anticipate. → Q-32; See also: [override-contract drift](#override-contract-drift), [exceptional class](#exceptional-class)

**exceptional class** — The pair of edge condition values `{exception, panic}` treated collectively for path-relative transience and query filtering. A predicate expressed as "non-exception path" or `exceptional()` in query language excludes both `exception` and `panic` edges. → GM-3 (under "Exceptional class"); See also: [edge condition](#edge-condition), [transience](#transience), [exception (edge condition)](#exception-edge-condition), [panic (edge condition)](#panic-edge-condition)

**file:line evidence** — Every node and edge in `cgx` carries a [provenance](#provenance) record that includes the repo-relative file path and 1-based line number of the source construct that produced it. This is a hard design constraint: no fact is emitted without file:line evidence. → GM-6, docs/01; See also: [provenance](#provenance)

**forward slice** → See [slicing](#slicing).

**framework pack** — A declarative configuration that maps (language, metadata pattern) pairs to graph facts. Packs teach `cgx` how a specific framework interprets annotations, decorators, attributes, or struct tags — what they mean for reachability, call routing, and analysis. `cgx` ships built-in packs for Spring, Flask/Django, ASP.NET, NestJS, tokio/actix, and others; users extend them via `cgx.toml`. → FW-1, docs/12; See also: [metadata fact](#metadata-fact), [semantic class](#semantic-class)

**function value** — A function or method used as a data value: stored in a variable, passed as an argument, returned, or placed in a collection. Represented in the dataflow graph as a symbol node with `kind: function-value`. Indirect-call resolution is pedigree computed over function values: the candidate callee set at an indirect call site is the set of function values that flow to the function-value variable at that site. → DF-18; See also: [pedigree](#pedigree), [closure](#closure), [lambda](#lambda)

**generated-member** — A metadata semantic class meaning the annotated symbol, or symbols derived from it, exist without developer-authored source (generated by an annotation processor, `#[derive(...)]`, Lombok, etc.). Generated symbols receive `macro_origin` provenance; call edges to them are valid targets for reachability. → GM-15.1, FW-2; See also: [metadata fact](#metadata-fact), [semantic class](#semantic-class)

**guard** — A metadata semantic class meaning the framework evaluates an authz/authc condition before invoking the annotated symbol — there is no explicit call to the check in source code. `cgx` inserts a synthetic `must-pass-through` fact for the symbol. This is the highest-stakes class: omitting it produces false authorization-bypass findings on all annotation-driven security codebases. → GM-15.1, FW-2.2, Q-31; See also: [metadata fact](#metadata-fact), [negative-guard](#negative-guard), [must-pass-through](#must-pass-through)

**guard_analysis** — The per-finding label that records which mode of the guarded-cut reachability algorithm (Q-20, ADR-02) was applied to a particular path. Two values: `"cut+dominance"` (every caller on the path had intraprocedural dominance facts; finding confidence is the min-edge confidence) and `"cut-only"` (at least one caller lacked dominance facts; finding confidence capped at `probable`; note names the unanalyzed callers). `guard_analysis: "cut-only"` is the degraded mode used in Phase 1–2 before Phase-3 dominance facts are populated. → ADR-02, Q-20; See also: [guarded-cut reachability](#guarded-cut-reachability), [dominance](#dominance), [confidence](#confidence)

**guarded-cut reachability** — The normative semantics of `MATCH ALL … MUST PASS THROUGH` and `MATCH ALL … AVOIDING` (Q-20, ADR-02). Given source S, sink T, and guard G, the algorithm builds a residual graph by: (1) deleting node G and its edges; and (2) deleting every call edge whose call site is dominated (in its caller's CFG) by a call to G. T is guard-protected if it is unreachable from S in the residual graph. Fixes the false-positive on the inline-sibling-guard pattern (`require_admin(); helper()`) where node-membership testing would incorrectly flag the path. Before Phase-3 dominance facts exist, the algorithm runs in cut-only mode and findings are capped at `probable`. → Q-20, ADR-02; See also: [dominance](#dominance), [must-pass-through](#must-pass-through), [call-site node](#call-site-node)

**implicit call site** — A location in source code where a function is invoked without explicit call syntax (Rust `Drop::drop` at scope exit, Python `__enter__`/`__exit__` in a `with` block, Go `defer`, iterator desugaring). `cgx` models these as `calls` edges with an `implicit:<kind>` attribute. They participate in effect computation, resource-pair tracking, and pedigree. → GM-16; See also: [resource lifecycle pair](#resource-lifecycle-pair), [edge](#edge)

**implicit:<kind>** — The attribute value family on implicit call edges that identifies the language mechanism that produced the implicit call. Defined kinds include `drop`, `destructor`, `deref`, `coercion`, `operator`, `iterator`, `context-enter`, `context-exit`, `property`, `defer`, `static-init`, and `conversion`. → GM-16.1; See also: [implicit call site](#implicit-call-site)

**include_dirty** — An MCP overlay flag (ADR-06) that controls whether uncommitted working-tree changes are incorporated into a query's graph context via the per-call content-addressed overlay. Default: `true` on all MCP tool calls (so an AI coding agent sees its own edits immediately); `false` on CLI invocations (which use the committed tree by default). When `true`, `cgx` computes a dirty-tree overlay keyed by a content digest of the modified files; the overlay is never written to the persistent index. → ADR-06, IX-3; See also: [overlay-digest](#overlay-digest--dirtydigest), [index](#index), [MCP](#mcp-model-context-protocol)

**index** — The persistent, content-addressed graph database that `cgx` maintains alongside the repository. Built automatically on first query; updated incrementally on subsequent queries. The index is read-only during query execution and is keyed by blob OID at Layer 1 (per-file facts) and tree OID at Layer 2 (cross-file graph). → IX-1, docs/06; See also: [blob OID](#blob-oid), [branch-aware incremental indexing](#branch-aware-incremental-indexing), [prune](#prune)

**interception** — A metadata semantic class meaning the call to the annotated symbol is rewritten at runtime to pass through a proxy, advice, or wrapper (e.g. Spring AOP `@Transactional`, `@Async`). `cgx` inserts a [mediated call edge](#mediated-edge) to the intercepting component; `@Async` additionally converts the call to a `spawns` edge. → GM-15.1, FW-2; See also: [mediated edge](#mediated-edge), [semantic class](#semantic-class)

**IS EMPTY** — A query-language predicate that evaluates to true when a type-reconstruction candidate set is empty, meaning the constraint intersection across the inference directions has no solution — a [type contradiction](#type-contradiction). Used in lineage type reconstruction queries (Q-26). → docs/05-queries.md Layer 2 "Predicates"; See also: [lineage type reconstruction](#lineage-type-reconstruction), [COMPATIBLE_WITH](#compatible_with), [type contradiction](#type-contradiction)

**keep-alive** — A metadata semantic class meaning the annotated field or method is accessed reflectively or by serialization even though no static call site exists in the graph. `cgx` sets `keep_alive: true` on the node so dead-member analysis (DF-7) does not report it as never-referenced. → GM-15.1, FW-2; See also: [metadata fact](#metadata-fact), [semantic class](#semantic-class)

**lambda** — A node kind (GM-1.1) representing an anonymous callable with a stable allocation site — closures, arrow functions, and lambda expressions. The allocation site is the program point where the lambda is defined; multiple runtime instances share one abstract identity. → GM-1.1; See also: [closure](#closure), [function value](#function-value), [capture edge](#capture-edge)

**Layer 1** — The focused-subcommand query interface: common questions expressed as dedicated commands (`callers`, `callees`, `paths`, `unused`, `pedigree`, `explain`, `diff`) with no query-language syntax. Every Layer 1 result is identical in content to the equivalent Layer 2 result. → docs/05-queries.md "Layer 1"; See also: [Layer 2](#layer-2)

**Layer 2** — The full query-language interface, accessed via `cgx query`. Accepts a Cypher-subset expression (ISO GQL-compatible) evaluated in-process against the indexed graph. The only escape hatch for questions that do not fit a Layer 1 subcommand; results are the same objects as Layer 1 produces. → docs/05-queries.md "Layer 2"; See also: [Layer 1](#layer-1), [MATCH](#match), [predicate](#predicate), [procedure](#procedure)

**lineage type reconstruction** — A query capability (Q-26, DF-19) that infers the type of a value from its usage context rather than its declaration. Three inference directions exist: `up` (from call sites that receive the value), `down` (from how the value is used), and `sideways` (from values it is compared with or assigned alongside). Type contradictions — when the intersected constraint set is empty — indicate potential bugs. → Q-26, DF-19; See also: [CALL … YIELD](#call--yield), [COMPATIBLE_WITH](#compatible_with), [IS EMPTY](#is-empty), [coerce](#coerce)

**linearization** — The algorithm that flattens a multiple-inheritance or trait/mixin graph into a single ordered ancestor list, resolving diamond ambiguity deterministically. The result is the type's [method resolution order (MRO)](#method-resolution-order-mro). Different languages use different linearization rules (Python C3, Scala trait linearization, Ruby ancestry, C++ virtual-base de-duplication), so `cgx` records the language's own result rather than a generic one. → GM-22; See also: [method resolution order (MRO)](#method-resolution-order-mro)

**lock set** — The set of synchronization objects held (acquired but not yet released) at a given call-site node. Stored as a conservative over-approximation. Used in queries for await-under-lock, inconsistent-lock-set, and double-acquire patterns. → GM-11; See also: [suspension point](#suspension-point), [resource lifecycle pair](#resource-lifecycle-pair)

**MATCH** — The core query-language clause that selects a pattern of nodes and edges from the graph. Combines with `WHERE` for filtering and `RETURN` for projection. The special forms `MATCH ALL … MUST PASS THROUGH` and `MATCH ALL … AVOIDING` express ∀-path quantifiers. → docs/05-queries.md "Query language syntax"; See also: [Layer 2](#layer-2), [predicate](#predicate), [path quantifier](#path-quantifier)

**MCP (Model Context Protocol)** — The protocol over which `cgx` exposes its query capabilities to AI coding and security agents. `cgx mcp` starts a STDIO server conforming to the 2025-06-18 MCP specification; tools include `callers`, `callees`, `paths`, `unused`, `explain`, `graph_query`, `taint_paths`, and `diff_security`. → docs/07-interfaces.md IF-9; See also: [STDIO mode](#stdio-mode)

**mediated edge** — A `calls` or `constructs` edge connecting a caller and a callee that are not syntactically linked — the binding is established at runtime by a DI container, event bus, or registry. Mediated edges carry an [established-by](#established-by) attribute and may retain the `via-DI` [cut marker](#cut-marker). → GM-17; See also: [established-by](#established-by), [cut marker](#cut-marker), [framework pack](#framework-pack)

**merge-base** — The most recent common ancestor commit of two branches. Branch-diff queries (Q-7 `diff`, Q-16) compare the graph at the current `HEAD` against the graph at the merge-base to isolate exactly the edges a branch introduced, rather than every difference between the two branch tips. → Q-7, IX-9, docs/06; See also: [branch-aware incremental indexing](#branch-aware-incremental-indexing)

**metadata fact** — A piece of metadata on a symbol — a Java annotation, C# attribute, Rust outer attribute, Python decorator, or Go struct tag — lowered to a graph fact by a [framework pack](#framework-pack). Each metadata fact belongs to one or more [semantic classes](#semantic-class). Metadata facts are attributes of symbol nodes, not a separate node type. → GM-15; See also: [framework pack](#framework-pack), [semantic class](#semantic-class)

**method resolution order (MRO)** — The ordered sequence of ancestor types a language searches to bind a method or `super` call on a given type. For single inheritance it is the `inherits` chain; for multiple inheritance, mixins, or traits it is the language's [linearization](#linearization) (Python C3, Scala trait linearization, Ruby ancestry, C++ virtual-base de-duplication). `cgx` stores it per type as the `mro` attribute. → GM-22; See also: [linearization](#linearization), [super call](#super-call), [virtual dispatch](#virtual-dispatch)

**must-pass-through** — A path-quantifier assertion that every path from a source to a sink passes through a named node. The ∀-path dual of ordinary [reachability](#reachability). Expressed as `MATCH ALL … MUST PASS THROUGH` in the query language or `--must-pass-through` in the `paths` subcommand. A guard annotation lowers to a must-pass-through fact without any call in source code. → Q-20, GM-15.1 (`guard`); See also: [path quantifier](#path-quantifier), [avoiding](#avoiding), [guard](#guard)

**mutability** — The `cgx` model distinguishes three levels. **Binding mutability** governs whether a name can be reassigned (`const` vs `var`). **Value mutability** governs whether an object's internal state can change (`&T` vs `&mut T` in Rust; `Object.freeze()` in JS). **Alias mutability** governs whether another reference can mutate the value through a separate binding (shared references in most languages). All three levels are independently queryable. → DF-17.1; See also: [mutation fan-out](#mutation-fan-out), [capture edge](#capture-edge)

**mutation fan-out** — The outbound dual of [pedigree](#pedigree): given a value V at program point P, the set of all aliases, parameters, and captures through which V may be mutated after P. Computed by forward traversal of escape, capture, and `writes-param(i)` / `writes-receiver` edges. Exposed as the `cgx.mutation_fanout` procedure. → DF-17.3, Q-27; See also: [pedigree](#pedigree), [CALL … YIELD](#call--yield), [mutability](#mutability)

**negative-guard** — A metadata semantic class meaning the annotation explicitly disables a protection that would otherwise apply (e.g. `@PermitAll`, `@AllowAnonymous`). Surfaced as a `protection-disabled` attribute; queryable as a filter in authorization-bypass queries. → GM-15.1, FW-2; See also: [guard](#guard), [metadata fact](#metadata-fact), [semantic class](#semantic-class)

**node** — A [symbol](#symbol) in the call graph. Every program entity — function, method, type, field, variable, module, constant, macro, lambda, or entrypoint — is a node. All nodes carry `kind`, `fqn`, `location`, `language`, `visibility`, and `confidence` attributes. → GM-1; See also: [symbol](#symbol), [edge](#edge)

**overlay-digest / `+dirty.<digest>`** — The `graph_version` suffix appended when a query runs against an uncommitted dirty-tree overlay (ADR-06). The digest is a content-addressed hash of the modified file set; two queries with the same `+dirty.<digest>` suffix were evaluated against identical working-tree content and their results are comparable. A bare `graph_version` (no `+dirty` suffix) indicates the query ran against a committed tree snapshot. → ADR-06; See also: [include_dirty](#include_dirty), [index](#index)

**override-contract drift** — A divergence between an override and the method it overrides in a contract the base established: the override introduces an exception/panic path the base lacked ([exception-contract widening](#exception-contract-widening)), drops a guard the base routed all paths through ([dropped guard](#dropped-guard)), or changes the field-write footprint. Detected by comparing the override's callee sub-graph against the base's under corrected ∀-path semantics. → Q-32; See also: [must-pass-through](#must-pass-through), [exception-contract widening](#exception-contract-widening), [dropped guard](#dropped-guard)

**path** — A sequence of nodes connected by directed edges, representing a chain of calls or data-flow steps through the program. Paths are the primary unit of analysis in `cgx` queries; path-relative properties such as [transience](#transience) are computed per path, not stored on individual edges. → GM-4, docs/05-queries.md; See also: [reachability](#reachability), [transience](#transience)

**path quantifier** — A query-language operator that reasons about the complete set of paths between two points. `∃-path` (the default `MATCH`) asks whether any path exists; `∀-path` (`MATCH ALL … MUST PASS THROUGH` or `MATCH ALL … AVOIDING`) asks whether all paths satisfy a condition. → Q-20, Q-21; See also: [must-pass-through](#must-pass-through), [avoiding](#avoiding), [dominance](#dominance)

**pedigree** — The inbound provenance fan-out of a value: the transitive DAG of [derives-from](#derives-from) edges rooted at that value, fanning backwards through all contributing values, computations, and external sources. Pedigree is the backward slice; it answers "what populated this value?" → DF-1, Q-5; See also: [derives-from](#derives-from), [slicing](#slicing), [mutation fan-out](#mutation-fan-out)

**possible** — The lowest [confidence](#confidence) tier. An edge is `possible` when the candidate set was over-approximated: name-based match with multiple candidates, `dyn Trait` dispatch, function pointer without points-to analysis, or duck-typed name match. Queries can filter to exclude `possible` edges to reduce noise. → GM-5.1; See also: [probable](#probable), [certain](#certain), [confidence](#confidence)

**predicate** — A boolean condition used in the `WHERE` clause of a query to filter nodes, edges, or paths. Built-in path predicates include `NONE(…)` (negative path constraint), `ANY(…)` (path-relative transience check), `COMPATIBLE_WITH` (type compatibility), and `IS EMPTY` (empty type-reconstruction set). → docs/05-queries.md "Predicates"; See also: [MATCH](#match), [Layer 2](#layer-2), [COMPATIBLE_WITH](#compatible_with), [IS EMPTY](#is-empty)

**probable** — The middle [confidence](#confidence) tier. An edge is `probable` when it was resolved heuristically with a small, credible candidate set: CHA/RTA virtual dispatch with few overrides, a unique name match in scope, or a SCIP reference narrowed by type inference. → GM-5.1; See also: [certain](#certain), [possible](#possible), [confidence](#confidence)

**procedure** — A named server-side computation invoked via [CALL … YIELD](#call--yield) in the query language. Only two procedures are defined: `cgx.type_reconstruct(value, direction)` (lineage type reconstruction) and `cgx.mutation_fanout(value)` (mutation fan-out). Procedures are used when a query requires constraint intersection across multiple graph-traversal directions simultaneously — something a single `MATCH` pattern cannot express. → docs/05-queries.md "Procedure calls"; See also: [CALL … YIELD](#call--yield), [Layer 2](#layer-2)

**provenance** — The evidence record attached to every node and edge: repo-relative file path, 1-based line (and optional column), the name of the producing rule, the resolution tier used, and the blob OID of the source file at index time. Provenance is the basis for `--evidence` and `--explain` output. → GM-6; See also: [file:line evidence](#fileline-evidence), [resolution tier](#resolution-tier)

**prune** — The `cgx prune` subcommand that removes stale index entries for branches that have been deleted and files that have been removed. Pruning is optional; the index auto-manages itself, but `prune` reclaims disk space. → IX-5, docs/06; See also: [index](#index), [branch-aware incremental indexing](#branch-aware-incremental-indexing)

**reachability** — The graph property that a symbol B is reachable from symbol A if any sequence of directed edges connects A to B in the graph. "Reachable" in `cgx` means "not proven unreachable by structural analysis" — it does not mean "proven feasible at runtime." All reachability queries are evaluated relative to the active [entrypoint](#entrypoint) set. → GM-7.3, docs/03 "Known Limits"; See also: [entrypoint](#entrypoint), [path](#path), [must-pass-through](#must-pass-through)

**reflective** — A cut-marker value meaning the call target is a string computed at runtime (reflection, `Class.forName`, `eval`, `getattr`). `cgx` still emits the edge; security engineers filter reflective edges *in* for taint analysis; dead-code analysts filter them *out*. The cut marker is never removed even when the string has a literal pedigree and a callee is inferred. → GM-5.3, GM-18; See also: [cut marker](#cut-marker), [dynamic](#dynamic)

**release** — The act of unlocking or closing a resource at the end of a resource lifecycle pair. `cgx` checks that every execution path from an acquire call — including [exceptional class](#exceptional-class) paths — reaches a release call. → GM-13; See also: [resource lifecycle pair](#resource-lifecycle-pair), [acquiring](#acquiring)

**resolution tier** — One of five numbered algorithms (0–4) that `cgx` uses to resolve call targets, from syntactic name matching (tier 0, `possible`) up to Andersen/Steensgaard points-to analysis (tier 4, `certain`). The active tier at index time is recorded in each edge's [provenance](#provenance). Tiers 0–2 ship in the initial release; tiers 3–4 are planned extensions. → GM-5.2; See also: [confidence](#confidence), [provenance](#provenance)

**resolves-to** — A derived edge from a `calls:virtual` or `calls:super` call site to the method body the type's [method resolution order (MRO)](#method-resolution-order-mro) selects, per candidate concrete type. Makes "which class actually implements the method this call resolves to" a direct lookup rather than a hierarchy walk. → GM-22; See also: [method resolution order (MRO)](#method-resolution-order-mro), [candidate set](#candidate-set)

**resource lifecycle pair** — A declared `(acquire, release)` symbol pair asserting that every execution path from an acquire call must reach a corresponding release call, including on [exceptional class](#exceptional-class) paths. Pairs are declared in `cgx.toml` or built into per-language defaults; `release` accepts a list so that any one of several release symbols satisfies the obligation. → GM-13; See also: [acquiring](#acquiring), [release](#release), [must-pass-through](#must-pass-through)

**roadmap** — A status tag applied to features that are designed but not yet committed to the current implementation cycle. Roadmap features may have reserved schema space but have no implementation milestone assigned. Query blocks for roadmap features are headed by `-- illustrative: requires <feature-id> (roadmap)`. → docs/11-roadmap.md; See also: [schema-room](#schema-room), [core-extension](#core-extension)

**sanitizer** — A declared call site whose output is considered free of a specific taint category. Under [class-matched sanitization](#class-matched-sanitization), a sanitizer clears taint only for the sink class it declares — a `html` sanitizer does not clear `sql` taint. → DF-5, DF-11; See also: [taint analysis](#taint-analysis), [class-matched sanitization](#class-matched-sanitization), [source](#source), [sink](#sink)

**schema-room** — A status tag applied to features whose graph schema must be reserved now to avoid a breaking schema change later, but whose full query surface or analysis is a later milestone. Queries for schema-room features are marked `-- illustrative: requires <feature-id> (schema-room)`. → docs/11-roadmap.md; See also: [core-extension](#core-extension), [roadmap](#roadmap)

**semantic class** — One of the seven categories into which [metadata facts](#metadata-fact) are lowered by a [framework pack](#framework-pack). The seven classes are: `entrypoint`, `guard`, `negative-guard`, `interception`, `generated-member`, `keep-alive`, and `contract`. Each class maps to a specific graph-fact change at index time. A single annotation may lower to more than one class. → GM-15.1, FW-2; See also: [metadata fact](#metadata-fact), [framework pack](#framework-pack)

**sink** — A declared program point where a tainted value reaching it constitutes a vulnerability (e.g. a SQL query string, a shell execution call, an HTML output write). Sinks carry a **sink class** (`sql`, `shell`, `html`, `path`, etc.) that determines which [sanitizers](#sanitizer) can clear taint targeting that sink. → DF-5, DF-12.2; See also: [source](#source), [sanitizer](#sanitizer), [typed taint](#typed-taint)

**site_id** — The identity of a specific call expression within a caller's body, carried as an attribute on call edges. A `site_id` uniquely identifies the call site by `(caller, file, line, col)` and is the join key used to access the corresponding call-site node via `r.site` in a query. The dominance-cut step in guarded-cut reachability (Q-20, ADR-02) uses `site_id` to look up `dominating_sites` for each call edge. → GM-1.4, GM-2.3, ADR-01; See also: [call-site node](#call-site-node), [guarded-cut reachability](#guarded-cut-reachability)

**slicing** — Program slicing computes the set of symbols that affect or are affected by a given symbol at a given point. A **backward slice** from S (pedigree) returns all symbols whose values may affect S. A **forward slice** from S returns all symbols that may be affected by S (downstream impact). Both directions cross function boundaries via function summaries. → DF-6; See also: [pedigree](#pedigree), [derives-from](#derives-from)

**source** — A declared program point where an untrusted or sensitive value enters the program (e.g. an HTTP request parameter, an environment variable, a database row). Sources carry a **source class** (`network`, `env`, `db`, `file`, `cli`, `deserialization`, `ipc`, `secret`) that identifies the trust boundary crossed. → DF-5, DF-12.1; See also: [sink](#sink), [sanitizer](#sanitizer), [typed taint](#typed-taint), [taint analysis](#taint-analysis)

**spawn context** — The detached execution context created by a [spawn edge](#call-edge) (GM-9): each spawned thread or task carries a distinct `spawn_context` identifier. Cross-spawn race queries (Q-24) compare the `spawn_context` of two field accesses to detect a shared field written from two concurrently-running contexts. → GM-9, GM-11, Q-24; See also: [lock set](#lock-set), [suspension point](#suspension-point)

**STDIO mode** — The mode in which `cgx mcp` runs as a Model Context Protocol server over standard input/output. AI agents send JSON-RPC tool calls on stdin; `cgx` replies on stdout. No daemon, no network port. → docs/07-interfaces.md IF-9; See also: [MCP](#mcp-model-context-protocol)

**string-pedigree** — The provenance classification of the method-name or class-name string that drives a [reflective](#reflective) dispatch site, recorded as the `string_pedigree` attribute (GM-18.1). Its values are `literal`, `constant`, `joined`, and `tainted`; a `tainted` string-pedigree on a reflective call is the highest-severity case, because attacker input controls which code executes. → GM-18.1, Q-31; See also: [reflective](#reflective), [pedigree](#pedigree), [taint analysis](#taint-analysis)

**super call** — A call that statically and non-virtually delegates to a named ancestor's method body, deliberately bypassing the override that [virtual dispatch](#virtual-dispatch) would otherwise select. Represented as a `calls:super` edge with a single resolved target and a `bypassed_override` attribute naming the override virtual dispatch would have selected. → GM-21; See also: [virtual dispatch](#virtual-dispatch), [override-contract drift](#override-contract-drift)

**suspension point** — A call site or expression where the current execution context yields control to a scheduler before resuming (Rust `.await`, Go channel operation, JavaScript `await`, Java `Future.get()`). Modelled as a `suspends = true` property on the call-site node. Suspension points are the TOCTOU primitive: shared mutable state may change between suspension and resumption. → GM-10; See also: [lock set](#lock-set), [transience](#transience)

**symbol** — A named program entity in the graph — function, method, type, field, variable, module, constant, macro, lambda, or entrypoint. Symbols are the nodes. Each symbol is identified by a fully-qualified name (FQN) and carries kind, location, language, visibility, and confidence attributes. → GM-1; See also: [node](#node), [edge](#edge)

**taint analysis** — The analysis that tracks whether a value originating at a [source](#source) can reach a [sink](#sink) without passing through a [sanitizer](#sanitizer). `cgx` uses an IFDS-style interprocedural propagation over [derives-from](#derives-from) edges, respecting field sensitivity and [container models](#transformation-kind). Under [typed taint](#typed-taint), sanitization is class-matched. → DF-5, DF-11; See also: [source](#source), [sink](#sink), [sanitizer](#sanitizer), [typed taint](#typed-taint)

**taint (source class)** — The taint label propagating through the graph carries a source class (e.g. `network`, `secret`) and a sink class (e.g. `sql`, `html`) as first-class attributes. This is distinct from the concept of taint as a binary "is tainted / is not tainted" flag. See [typed taint](#typed-taint).

**transformation kind** — The semantic characterization of a [derives-from](#derives-from) edge: how the derived value relates to its source in terms of security effect. Built-in kinds include `copy`, `projection`, `parse`, `serialize`, `concat`, `encode(class)`, `parameterize(class)`, `validate(class)`, and `coerce(from,to)`. Kinds such as `parameterize(sql)` clear taint for the named sink class; others are taint-preserving. → DF-10; See also: [derives-from](#derives-from), [typed taint](#typed-taint), [coerce](#coerce)

**transience** — A path-relative property, computed at query time, never stored as a fixed edge attribute. An edge C→D is exception-transient relative to path P if and only if P traverses at least one edge in the [exceptional class](#exceptional-class) before reaching C. The same edge is not exception-transient relative to a different path P′ that reaches C with no exceptional edge. Transience is computed by a per-walk `seen_exceptional` flag maintained during graph traversal. → GM-4; See also: [exceptional class](#exceptional-class), [path](#path), [edge condition](#edge-condition)

**trust boundary** — A point in the data flow where a value transitions from a lower-trust context into program-controlled processing. Defined by the [source class](#source) of the originating value. Distinct from code-trust boundaries (GM-14), which are compile-time and link-time concerns (unsafe regions, FFI, reflection, dependency edges). → DF-12.3, GM-14; See also: [source](#source)

**type-confidence boundary** — A program point where the static type of a value stops constraining call-target resolution or taint classification. Arises from language escape hatches: TypeScript `any`, Go `interface{}`/`any`, C# `dynamic`, reflection results, and broad-interface casts. Any node reachable only via a type-confidence-boundary transition carries at most `possible` confidence. → GM-14.6, DF-19; See also: [confidence](#confidence), [lineage type reconstruction](#lineage-type-reconstruction), [coerce](#coerce)

**type contradiction** — The outcome of a [lineage type reconstruction](#lineage-type-reconstruction) query in which the type constraints gathered from the up, down, and sideways directions have an empty intersection: no single type satisfies all the observed uses of the value. A contradiction indicates a likely bug — the code treats one value as two incompatible types. Detected in the query language with the [IS EMPTY](#is-empty) predicate. → DF-19, Q-26; See also: [lineage type reconstruction](#lineage-type-reconstruction), [IS EMPTY](#is-empty), [COMPATIBLE_WITH](#compatible_with)

**typed taint** — The refinement of basic taint analysis in which every taint label carries both a source class and a sink class as attributes, and sanitizers are evaluated against the sink class of the label rather than globally. Prevents cross-context false negatives (e.g. HTML-escaping a value that later reaches a SQL sink). → DF-11; See also: [taint analysis](#taint-analysis), [class-matched sanitization](#class-matched-sanitization), [source](#source), [sink](#sink)

**unexpanded-macro marker** — A cut-marker value (`unexpanded-macro`) on a call edge emitted at a proc-macro invocation site where the code generated by the macro was not expanded at index time. Call edges that may exist inside the generated code are absent; the marker makes the gap visible and countable via `cgx doctor`. Edges carry this marker by default; the `--rust-expand` roadmap flag populates expansion-derived edges instead. → GM-5.3, ADR-07; See also: [cut marker](#cut-marker)

**union/join pedigree** — A join node in the pedigree graph that makes a multi-source assembly point explicit and queryable. Inserted when two or more distinct `derives-from` edges converge on a single derived value through structural assembly (not conditional branching). Join nodes have kind `join`, carry an arity and site, and enable queries that reason about the combination of sources (e.g. "derives from both a network source and a db source"). → DF-9; See also: [pedigree](#pedigree), [derives-from](#derives-from)

**unresolved** — A cut-marker value meaning resolution was attempted and produced no candidates — the symbol is genuinely unknown to `cgx`. → GM-5.3; See also: [cut marker](#cut-marker)

**vacuity guard** — A runtime check in `cgx`'s assertion mode (ADR-08) that detects when an `--assert-empty` gate passed vacuously: either the `--from`/`--to` symbol pattern matched zero symbols, or the confidence/edge-condition filters excluded every result the unfiltered query would have returned. Vacuous passes exit with code 4 unless `--allow-vacuous` is given. Prevents silent false-safety in CI pipelines where a `--confidence certain` gate is vacuous before SCIP-resolution ships. → ADR-08, docs/07 IF-4, IF-5; See also: [confidence](#confidence)

**via-DI** — A cut-marker value meaning the binding is managed by a dependency injection container (Spring, Guice, Dagger, CDI). The edge is still emitted with this marker so the gap is visible; the `established-by` attribute records what evidence was used when a binding can be inferred. → GM-5.3, GM-17.3; See also: [cut marker](#cut-marker), [mediated edge](#mediated-edge), [established-by](#established-by)

**via-FFI** — A cut-marker value meaning the call crosses a foreign-function boundary (JNI, Python C extensions, Rust `extern "C"`, CGO). Behaviour inside the foreign code is not modelled; confidence falls to `possible` for the resolved target. → GM-5.3; See also: [cut marker](#cut-marker)

**view_schema_version** — An integer exposed by the `cgx_meta` SQL view that records the current schema revision of the versioned `v_*` SQL views (`v_symbols`, `v_call_edges`, `v_call_sites`, `v_provenance`). View-breaking changes — column renames, type changes, row-set changes — bump this integer. Scripts using the `--sql` escape hatch (Q-10, ADR-05) should pin `view_schema_version` to detect incompatible upgrades. Physical tables are not API and carry no stability guarantee. → ADR-05, Q-10; See also: [Layer 2](#layer-2)

**virtual dispatch** — Dispatch through a virtual, interface, or trait method where the runtime target depends on the concrete type of the receiver. Represented as a `calls:virtual` edge with a [candidate set](#candidate-set) listing all possible targets. Confidence is `probable` when CHA/RTA narrows the set, `possible` when it cannot. → GM-2.1, GM-5; See also: [candidate set](#candidate-set), [confidence](#confidence)

**weakest-link confidence** — The lowest [confidence](#confidence) tier among all edges on a path, computed as `MIN([e IN relationships(path) | e.confidence])` under the ordering `certain > probable > possible`. A reachability path is only as trustworthy as its weakest edge; a path whose weakest link is `possible` may be a false positive from over-approximated dispatch. → GM-5, Q-25 (Worked Example 5); See also: [confidence](#confidence), [possible](#possible), [reachability](#reachability)

**worktree awareness** — The property of `cgx`'s index that treats each git worktree as a first-class indexing context sharing blob-OID-addressed per-file facts with the main checkout. Unchanged files cost nothing to re-index regardless of which worktree is queried. → IX-6; See also: [branch-aware incremental indexing](#branch-aware-incremental-indexing), [blob OID](#blob-oid)
